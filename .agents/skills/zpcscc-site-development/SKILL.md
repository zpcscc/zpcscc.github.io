# zpcscc 站点开发

遵循仓库已经形成的实现模式，避免另起一套样式体系或工具链。

## 必须执行的流程

1. 修改站点代码前，完整阅读[项目开发规范](references/project-conventions.md)。
2. 设计改动前，检查最接近的同类组件、演示、文档及相关配置。
3. 保持 pnpm、Docusaurus 插件边界、路径别名和现有目录结构不变。
4. 使用 UnoCSS 原子类实现样式。仅在第三方全局选择器或 UnoCSS 无法表达所需行为时新增样式表，并在交付说明中记录这个例外。
5. 继续使用现有的 `createClientDemo` 动态导入模式隔离仅浏览器运行的库。
6. 将外部服务接入界面前，根据第一方文档和真实、有代表性的响应完成验证。
7. 依次运行改动范围内的格式化、代码检查、TypeScript 类型检查和生产构建。修复本次改动引入的问题，并区分无关的既有警告。

## 决策规则

- 优先复用项目现有组件和库，不要轻易新增依赖。
- 按照 `package.json` 的现有方式，将依赖锁定为精确版本。
- 使用静态、完整的 UnoCSS 类名字符串，确保提取器可以识别。需要条件样式时，通过 `classnames` 或映射表在完整类名字符串之间选择。
- 仅将运行时计算结果放入行内 `style`，例如画布尺寸、坐标、不透明度或变换值。
- 将可在全站复用的 UnoCSS 快捷方式放入 `uno.config.ts`；将功能专用的原子类保留在对应 JSX 附近。
- 功能需要适配亮色和暗色主题时，使用 Docusaurus 主题 CSS 变量。
- 保持 HTML 可访问性：根据控件用途设置按钮类型、标签、状态角色、焦点状态和键盘行为。
- 不要编辑生成的构建产物或生成的 UnoCSS 输出文件。

## 交付要求

说明用户可见的结果、受影响的路由或界面、数据源限制以及已经执行的检查。只报告与本次改动仍然相关的警告。
